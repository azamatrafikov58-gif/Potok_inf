# Фабрика Новостей (NRCS Newsroom Core)

Веб-платформа полного цикла для централизации и ускорения производства новостного контента — от получения исходного материала и планирования съёмки до выхода выпуска в эфир.

---

## 1. Реализованная функциональность

### Единая карточка новости и статусная модель
Каждая новость проходит через сквозной конвейер из 8 этапов с возможностью возврата на доработку:
`Заявка` → `Съёмка` → `В работе` → `Текст готов` → `Монтаж` → `Проверка` → `Утверждено` → `В эфире`

### Ролевая модель (RBAC — 9 ролей)
Переходы между статусами контролируются на уровне бэкенда. Система объединяет в едином пространстве:
- **Администратор-продюсер:** создание новостных заявок, планирование съёмок, назначение экипажа.
- **Телеоператор:** работа со съёмочным этапом, привязка медиафайлов S3.
- **Журналист:** написание текста сюжета, разметка таймкодов.
- **Редактор / Шеф-редактор:** вычитка, утверждение текста, возврат на доработку, общий контроль.
- **Монтажёр / Режиссёр монтажа:** выгрузка проекта для монтажных станций, приёмка сборки.
- **Выпускающий режиссёр:** запуск веб-телесуфлёра, перевод сюжета в прямой эфир.

## 2. Адаптерный слой интеграций
- **Монтажные станции (NLE):** генерация и скачивание `.xml` файла проекта с разметкой и медиассылками (совместимо с Adobe Premiere Pro, DaVinci Resolve).
- **Внешние источники (Ingest):** импорт новостных поводов из лент информагентств (ТАСС / РИА) в один клик.
- **Хранилище медиа (S3 / NAS):** привязка исходников и готовых сборок к объектному хранилищу на территории РФ.
- **Студийное вещание:** встроенный полноэкранный режим веб-телесуфлёра.
- **Аутентификация и уведомления:** архитектура готова к подключению корпоративного SSO / Active Directory (LDAP) и шлюзов оповещений.

---

## 3. Информационная безопасность, 152-ФЗ и SLA 99.5%
- **Соответствие 152-ФЗ:** полная автономность системы — отсутствуют внешние CDN, шрифты, трекеры и зарубежные облачные зависимости. Все данные и медиафайлы локализуются в контуре на территории РФ.
- **Неизменяемый журнал аудита:** каждое действие пользователя (создание карточки, редактирование текста, экспорт XML, смена статуса) записывается в таблицу `audit_logs` с фиксацией времени, роли и IP-адреса.
- **Отказоустойчивость (SLA 99.5%):** настроена политика автоматического перезапуска контейнеров (`restart: unless-stopped`), контроль готовности БД (`healthcheck`) и постоянное хранилище данных (`volumes: pg_data`).

---

## 4. Технологический стек
- **Backend & Web UI:** Python 3.12 (`http.server`, драйвер `pg8000`)
- **База данных:** PostgreSQL 16
- **Контейнеризация:** Docker, Docker Compose

---

## 5. Инструкция по запуску

### Вариант А. Запуск в Docker с PostgreSQL (Production / Контур заказчика)
1. Перейдите в директорию с файлами проекта (`app.py`, `Dockerfile`, `docker-compose.yml`).
2. Выполните команду сборки и запуска:
   ```bash
   docker compose up --build -d
   ```
3. Откройте веб-интерфейс в браузере по адресу: **`http://localhost:8090`**

### Вариант Б. Локальный запуск (Demo-режим без Docker)
Если переменная `DATABASE_URL` не задана, платформа автоматически запускается в автономном демо-режиме:
```bash
python3 app.py
```
Веб-интерфейс будет доступен по адресу: **`http://127.0.0.1:8090`**
